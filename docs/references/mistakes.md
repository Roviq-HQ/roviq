# Quick Mistake Reference — full detail

Compressed one-liners live in `CLAUDE.md`. This file keeps the full rationale and the CI gate that enforces each rule.

| Don't                                                      | Do                                                                                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `selectInstitute(tenantId)`                                | `selectInstitute(membershipId)`                                                                                                                               |
| `User.abilities`                                           | `Membership.abilities` (abilities live on Membership)                                                                                                         |
| `$transaction` / `withTenant(db, tenantId, fn)`            | `withTenant(db, ctx, fn)` — pass the branded `InstituteContext` (after `assertTenantContext(user)`) or `mkInstituteCtx(tenantId)` for synthetic callers. Same shape for `withReseller(db, ctx, fn)` and `withAdmin(db, ctx, fn)`. `tenantTransaction()` does not exist. |
| `err.message.includes('Password changed')`, showing `err.message` to the user | Branch on `extensions.code`: `isAppError(err, code)` / `extractErrorCode` in `@roviq/auth`, `extractGraphQLErrorCode` in `@roviq/graphql`; show translated copy (`resolveAuthErrorMessage`, `t(code)`). |
| `throw new UnauthorizedException('Invalid credentials')` where the client must tell failures apart | `throw new BusinessException(ErrorCode.INVALID_CREDENTIALS, 'Invalid credentials')` — add the code + status to `error-codes.ts`. |
| `if (role === 'teacher')`                                  | `ability.can()`                                                                                                                                               |
| `GqlAuthGuard` from `@roviq/casl`                          | `GqlAuthGuard` from `@roviq/auth-backend`                                                                                                                     |
| `APP_GUARD` for scope isolation                            | `@PlatformScope()` / `@ResellerScope()` / `@InstituteScope()` at class level                                                                                  |
| Raw `<button>`                                             | `<Button>` from `@roviq/ui`                                                                                                                                   |
| Inline `<Popover>` + lucide `HelpCircle` next to a label; a `<FieldDescription>` or muted `<p>` between a label and its input | A help topic in `apps/web/src/help/<area>/<form>.help.ts` (`defineFieldHelp`, `en` and `hi` together) passed as `help={…}` to the shared field or `FieldLabelWithInfo`: it renders the ⓘ popover and the optional hint. An instruction needed to fill the field goes in `description`, after the input. Gate: `pnpm check:field-help`. Detail: `docs/frontend.md` → "Field help" |
| `toast.error(…)` in a form's `onSubmit` or `onSubmitInvalid` | The error stays in the form, where a slow reader can still act on it: `setServerFieldError(form, field, message)` when it is about one field, otherwise `setFormSubmitError(form, { title, description })` with `<form.SubmitError />` directly above the submit button. Toasts are for success, undo and actions with no form. Gate: `pnpm check:form-errors` (older forms are listed in `scripts/form-errors-baseline.json`, and a count only goes down). Detail: `docs/frontend.md` → "Error messages" → "Where it shows" |
| Hardcoded UI strings                                       | `useTranslations()` from `next-intl`                                                                                                                          |
| `new Date().toLocaleDateString()`                          | `useFormatDate()` from `@roviq/i18n`                                                                                                                          |
| Nav href `/dashboard`                                      | Include scope prefix: `/admin/dashboard`, `/institute/dashboard`                                                                                              |
| Writing docs/assertions from memory                        | Verify against actual source code before writing                                                                                                              |
| New `@roviq/*` lib without vitest alias                    | Add to `apps/api-gateway/vitest.config.ts` `resolve.alias` too                                                                                                |
| A URL column for a file, a typed-in file URL, or a direct S3 call | Reference `files.id`. Upload with `<FileUpload>` → pass `fileIds` → `FileService.verifyUploads` + `markFilesReady(tx, …)`; return `FileRef`. Storage only through `@roviq/storage` (`docs/architecture.md` → "File storage") |
| Hardcoded Redis key prefixes                               | Use `REDIS_KEYS` constants from `auth/redis-keys.ts`; a library names its own prefix in a constant. CI guard: `pnpm check:store-keys`, which also covers workflow handles, loaders, subscription filters and storage calls (`docs/architecture.md` → "Stores outside PostgreSQL") |
| Impersonation token refresh                                | Impersonation tokens are non-renewable. No refresh token created                                                                                              |
| `defaultRandom()` or `gen_random_uuid()`                   | `.default(sql`uuidv7()`)` (PG 18 native)                                                                                                                      |
| E2E locators: `getByRole`, `getByText`, `getByPlaceholder` | `page.getByTestId('…')` — Playwright's default `data-testid` attribute (NOT `data-test-id`). Add `data-testid="foo"` on the target element in production code |
| Re-running tests/builds to see different output            | Save to temp file first: `pnpm test > /tmp/out.txt 2>&1`, then `grep`/`tail` from file                                                                        |
| Querying e2e DB as `roviq` default                         | E2E uses `roviq_test` DB: `psql -U roviq -d roviq_test`                                                                                                       |
| `tx.select().from(subjects)` for reads (and other soft-deletable tables) | `tx.select().from(subjectsLive)` — every soft-deletable table has a `<table>Live` security_invoker view that hides trashed rows. Writes still target the base table (`tx.insert(subjects)…`). CI guard: `pnpm check:live-views`. `withTrash()` removed |
| `@Inject('JETSTREAM_CLIENT') natsClient` + `natsClient.emit('STUDENT.updated', …).subscribe(...)` in services | Inject `EventBusService` and call `eventBus.emit(EVENT_PATTERNS.STUDENT.updated, payload)` — wraps NATS JetStream + GraphQL pubsub. `pattern` is typed as `EventPattern` (typo = compile error). Direct `natsClient.emit('…')` outside the typed-wrapper allowlist fails `pnpm check:direct-nats-emit`. Every prefix MUST have a stream in `libs/backend/nats-jetstream/src/streams/stream.config.ts` (registry-coverage tests run as part of `nats-jetstream:test`) |
| `@EventPattern` handler class registered in a module's `providers`, or an app whose `main.ts` never calls `connectJetStreamMicroservice()` | Nest scans only `controllers` for message patterns, and without a connected transport nothing subscribes — the events reach NATS and are never consumed (ROV-316). Put the class in `controllers`, connect with `connectJetStreamMicroservice(app, options)` in `main.ts` + `await app.startAllMicroservices()` (a bare `app.connectMicroservice()` skips the filter that keeps the handler's real error). Several handlers of one subject share one durable and must declare the same extras (gateway: `gatewayConsumer(pattern)`). CI gate: `pnpm check:event-handlers` |
| `if (!user.resellerId) throw new ForbiddenException(...)` inline in resolvers | `assertPlatformContext(user)` / `assertResellerContext(user)` / `assertTenantContext(user)` / `assertInstituteWithReseller(user)` from `@roviq/auth-backend` — narrows the branded `AuthUser` union and centralises the 403 error shape. The last replaces the old `assertReseller + assertTenant` double-assert that narrowed to `never` |
| `mkAdminCtx()` / `mkResellerCtx()` / `mkInstituteCtx()` imported by a resolver or business service | These factories bypass JWT scope and only belong in workflow activities, seeders, repositories invoked from event consumers, and integration-test fixtures. New importers fail `pnpm check:synthetic-context-usage` until the file is added to `SYNTHETIC_CONTEXT_ALLOWLIST` with security review |
| An institute- or reseller-scope resolver reaching a repository or service that runs as admin (`withAdmin` / `mkAdminCtx`) | The admin role bypasses RLS, so a caller-supplied id reads or writes another tenant's rows (ROV-290). Platform-level operations belong in `admin/` resolvers; non-platform scopes use `withTenant` / `withReseller`, or verify ownership first. A newly reached admin-context function fails `pnpm check:admin-context-reach` until it is listed in `ADMIN_METHOD_ALLOWLIST` with the reason |
| A new institute- or reseller-scope operation that takes an id, with no test that sends another institute's id | Write the foreign-id test (`testing-integration` skill → "What every new or changed operation needs") and add the operation to `apps/api-gateway/src/__tests__/foreign-id-coverage.ts` with its spec. `foreign-id-coverage.spec.ts` fails the unit suite for an operation without an entry (ROV-293). The tests found `createStudent` storing another institute's section id: a foreign key does not apply RLS |
| Local `diffDays` / `assertValidRange` per service | `calendarDaysBetween` / `isValidDateRange` / `rangesOverlap` from `@roviq/common-types/date-range` |
| Inline `STATUS_TRANSITIONS: Record<string, string[]>` map + private `validateTransition()` per service | `defineStateMachine<S>(name, transitions)` from `@roviq/common-types`. Domain machines: `INSTITUTE_STATE_MACHINE`, `LEAVE_STATE_MACHINE`, `STUDENT_ACADEMIC_STATE_MACHINE`, `ADMISSION_APPLICATION_STATE_MACHINE`. Adding an enum value without listing transitions = compile error. Throws `BusinessException(ErrorCode.INVALID_STATE_TRANSITION)` (HTTP 422) |
| Adding a new soft-deletable table without a `<table>Live` view; adding a `pgTable` without RLS policies | Three CI gates: `pnpm check:live-views` (bans base-table reads), `pnpm check:live-views-coverage` (every soft-deletable table has a `*Live` export), `pnpm check:rls-coverage` (every `pgTable` opts into RLS; `RLS_EXEMPT_BASENAMES` is empty and an addition needs a security review) |
| Editing the Drizzle schema and expecting Tilt or the tests to pick it up; creating an index, unique rule or foreign key in a custom migration when the schema can declare it | Every database is built by `drizzle-kit migrate` (ROV-338): generate the migration in the same change. Custom SQL is only for what the schema cannot express (functions, triggers, grants, FORCE RLS, partitions); an object made there is invisible to the schema and drifts. `pnpm check:migrations` builds an empty database from the chain and fails on a table without FORCE RLS or a schema change no migration carries |
| A guarded operation that a role reaches only through a rule with a condition (own rows, linked children, assigned sections), without applying the condition to the rows | Apply the condition (a `caslToSqlWhere` predicate, or `ability.can()` on the loaded row), declare `@CheckAbility({ action, subject, rows: 'scoped' })` and list the operation in `row-scope-coverage.ts` with its refusal spec. Without the declaration `AbilityGuard` refuses the conditional role; `row-scope-coverage.spec.ts` fails on a missing declaration or registry entry (`docs/auth.md` → "CASL Authorization") |
| Adding a `@CheckAbility({ action, subject })` for a pair no role can reach (silent 403) or granting an ability no resolver checks (permission noise) | `apps/api-gateway/src/__tests__/ability-coverage.spec.ts` enforces both directions — every used pair must be reachable by ≥1 role (with manage/all expansion); every grant must be referenced by ≥1 resolver. Future-feature placeholders go on the explicit `allowGrantedButUnused` set |
| `data-testid="institute-row-{id}"` literal in new `apps/web/src` tsx, `libs/frontend/ui` components, or e2e specs | `data-testid={layout.row(id)}` (after `import { testIds } from '@roviq/ui/testing/testid-registry'; const { layout } = testIds;`). Registry lives in `@roviq/ui` so `libs/frontend/ui` components, `apps/web` pages, and `e2e/*` specs all import the SAME constant — drift between code and test is structurally impossible. Destructure the group at module top when a file uses 2+ testids; otherwise inline `testIds.<group>.<key>` is fine. CI gate `pnpm check:testids` is **deny-by-default** for `apps/web/src`: any literal `data-testid="…"` fails unless (a) the file is in the `LEGACY_FILES` grandfather list (migrate file-by-file then drop the entry), (b) the file lives under `__tests__/`, or (c) the line carries `// allow-testid-literal: <reason>`. New files must use the registry from day one |
| Hardcoded seed credentials / institute names in an e2e spec, `e2e/shared/e2e-users.ts` or a `scripts/seed-*.ts` script | Single source `e2e/shared/seed-fixtures.ts` exports `SEED_CREDENTIALS`, `SEED_NAMES`, `SEED`, `E2E_USERS`. `e2e/shared/e2e-users.ts` is a deprecated re-export shim |
| A security rule enforced only in a service or resolver ("only the platform may…", "suspension revokes…") | Enforce it in PostgreSQL too: GRANT, RLS policy, CHECK or trigger, so no code path can skip it (ROV-102). Test it by assuming the role and attempting the forbidden write, expecting a refusal — never by writing a value and reading it back. Rules the database cannot see (access tokens, Redis tickets) stay in the application and are tested through the API |
| Inserting a row whose foreign keys come from the caller (`studentProfileId`, `academicYearId`, `standardId`) without reading them first | Foreign-key checks do not apply RLS, and `WITH CHECK` sees only the new row's `tenant_id`, so another institute's id is accepted (ROV-322, SF-053). Read each id through its `*Live` view inside the caller's `withTenant` first and answer the entity's not-found code; also check the ids agree with each other (the class belongs to the year, the section to the class). Add a test that passes another institute's id for every id the operation takes |
| Declaring a reference from one tenant table to another with `.references()` | A single-column key accepts another institute's row for every role. Declare it with `sameTenantForeignKey()` on `(column, tenant_id)`, give the referenced table a unique index on `(id, tenant_id)`, and add the key to `same-tenant-foreign-keys.integration.spec.ts` (`pnpm check:tenant-foreign-keys`). An `ON DELETE SET NULL` reference is added in custom SQL with `SET NULL (column)` and listed in the check. The read before the write stays: it gives the entity's not-found code |
| A service that injects `DRIZZLE_DB` and calls `withTenant(...)` itself, with a unit spec that mocks the transaction as a queue of results | Queries scattered through a long service are hard to review for tenant isolation, and a mocked transaction proves nothing about the SQL (both defects found in ROV-315 and ROV-322 were in such services). Put every query in the feature's repository (`repositories/<name>.repository.ts` + `.drizzle-repository.ts`), one method per unit of work; the service keeps the rules and is unit-tested against a mocked repository. CI gate: `pnpm check:service-db-access` |
| An alert that fires on one event built as `increase(counter[5m]) > 0` (or `rate()`), or a dashboard count taken from a counter's `increase()` | A counter's series starts again at 1 with each process, and a series born at 1 has no increase, so the first event after a restart is never seen (ROV-336). A lasting condition (a breaker open, a sender blocked) is a gauge read from where the state is kept; an event is a gauge of the rows written in the window; a count shown to people is read from the database. Gate: `scripts/__tests__/notification-alerts.spec.ts` refuses `increase()`, `rate()` and `delta()` in a notification rule that fires above 0 |
